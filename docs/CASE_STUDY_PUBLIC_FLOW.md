# Case study public flow (zero-cost)

`CASE_STUDY_PARTICIPANTS = 0/3` until a person completes all steps below **and** is adjudicated in the participant ledger.

This is not a signup form, payment funnel, or customer list. Stars, pageviews, and “I might try it” do **not** count.

---

## Step 1 — TRY

Pick one AYEIXA open-source utility and evaluate it in a **real** workflow (local clone + build is fine):

| Project | Repository |
|---------|------------|
| OpenCoordinator | https://github.com/alpallovy/ayeixa-open-coordinator |
| FuelLite | https://github.com/alpallovy/ayeixa-fuellite |
| Sentience Eval | https://github.com/alpallovy/ayeixa-sentience-eval |
| MCP Guardian | https://github.com/alpallovy/ayeixa-mcp-guardian |
| Agent Memory Spine | https://github.com/alpallovy/ayeixa-agent-memory-spine |

Minimum try evidence (at least one):

- `npm install && npm test` output (paste redacted summary), **or**
- Integration notes (what you wired, what broke), **or**
- A GitHub issue/PR/discussion comment with concrete technical detail

---

## Step 2 — FEEDBACK

Share feedback on the **same repo’s GitHub Discussions** (linked from each README) or via a GitHub issue:

- What you tried
- What worked / failed
- Negative results welcome
- No payment required

Feedback must be **concrete** — not “looks cool” or star-only.

---

## Step 3 — OPTIONAL CASE STUDY CONSENT

Only if you want your experience considered for a published case study:

1. Read [`CASE_STUDY_CONSENT.md`](./CASE_STUDY_CONSENT.md)
2. Post a **new comment** on [Discussion #6](https://github.com/alpallovy/ayeixa-open-coordinator/discussions/6) (or your feedback thread)
3. **Explicitly choose exactly one:**
   - **NAMED** — publication may attribute your GitHub handle
   - **ANONYMOUS** — publication may use workflow/outcomes only
   - **NO_CASE_STUDY** — feedback welcome; do **not** use my experience in a case study

Implied consent is **not** accepted. Silence defaults to **NO_CASE_STUDY**.

---

## What we do not claim

- No existing user count or customer base is implied
- Founder outreach posts are invitations, not evidence of adoption
- Participation does not increment `CASE_STUDY_PARTICIPANTS` until all qualification gates pass
